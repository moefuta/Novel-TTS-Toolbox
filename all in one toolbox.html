Epub阅读器 TTS 使用说明书

本说明已根据工具箱当前版本全面重写。服务端接入、规则系统、Ruby 注音、工具箱各标签页操作均以本页为准。

⚠️ 为什么这个项目要专门为日文 TTS 做如此复杂的适配？
简单来说：中文和英文的 TTS，基本是“打开即用”的。英文只要把字符扔进去就行；中文虽然有多音字，但现代 TTS 引擎依靠上下文基本能解决 95% 的问题，最多配点基础标点规则。

但日文在 TTS 领域的难度，简直是屎山代码级别的一大坨答辩。因为日文是“表意汉字”和“表音假名”的无缝混排，且不说同一个汉字可能有几十种读音（音读、训读、熟字训），光是助词（如 は 读作 わ）、连浊（如 一ケ月 要读成 いっかげつ）、促音便（如 がつこう 变 がっこう），就能让普通的 TTS 引擎直接原地崩溃，读出来的声音堪比外星语。

更要命的是，EPUB 小说中的排版极其混乱。为了彻底解决这个问题，本项目做了极其庞大的底层努力：
  • 开发了极其复杂的正则与词典权重系统（支持多读音概率、优先级覆盖、前后缀阻断）。
  • 写了容错率极高的 Ruby 注音解析器（兼容 6 种以上的日文注音格式，自动合并被拆碎的单字注音）。
  • 加入了“疑似小字错标”与“人名专属后缀”引擎，用来兜底那些排版烂到极致的原始 EPUB 文件。
  • 做了一整套前端提取工具箱，让你能可视化地把看不过眼的错标读音手动纠正过来。
可以说，你在这个网页上看到的每一个配置项，都是无数日文小说 TTS 踩坑后总结出的血泪史。希望它能让你在听日语小说时，不再被“棒読み（毫无感情的机械朗读）”折磨。

① 安装 Python 环境与依赖库

推荐 Windows 11 使用 Python 安装管理器。已有 Python 3.10+ 的可跳过本节。

  1. 打开 Python 官网：https://www.python.org/downloads/，点击黄色按钮下载最新版本（推荐 .exe 或 .msix）。
  2. 双击下载的文件。确认发布者是 "Python Software Foundation"，点击"安装"。（如果是 exe 安装包，请务必勾选底部的 "Add Python.exe to PATH"）。
  3. 如果双击 .msix 文件没反应，请右键 → "打开方式" → 选择 "应用安装程序"。
  4. 按下 Win + R，输入 cmd 并回车。此时弹出的黑窗口，请勿关闭它。在黑窗口中输入：
    py install 3
  5. 安装完成后，输入 py --version，显示版本号（如 Python 3.12.0或更高）即成功。
  6. 继续在黑窗口中输入以下命令，安装 TTS 服务基础依赖库：
    py -m pip install fastapi uvicorn httpx pydantic pywin32
    py -m pip install edge-tts
    💡 关于 edge-tts：这是微软 Edge 在线语音引擎的依赖库。如果不需要使用此引擎，即使不安装它，也完全不会影响其他任何功能。
    🚫 常见报错：一定要看清行首符号！
    确认你当前所在的位置行首是 C:\Users\你的用户名>，如果行首变成了 >>>，说明你进入了 Python 内部环境，此时输入 pip 命令会报错。
    解决方法：输入 exit() 退出 Python 内部，回到带有 C:\... 的普通窗口后，再执行上面的 pip 命令。

3⃣ 核心机制：规则文件优先级

所有替换规则放在 📂replace_rules/ 目录，全部为 UTF-8 编码的*.txt。
改完任意文件后无需重启，下一次合成自动热重载。

基础语法

# 以 # 开头为注释，空行忽略
原文 => 替换文本

大小写、全半角（ABC / ａｂｃ）自动兼容。
原文中夹杂的半角/全角空格会被自动忽略（終　章 能命中 終章 => しゅうしょう）。

加权随机（多读音）

お兄ちゃん => おにいちゃん|おにいさま|あにき
お兄ちゃん => おにいちゃん(70%)|おにいさま(20%)|あにき(10%)

多个选项用 | 分隔，等概率随机。写 (N%) 表示权重，也可写 (7) 等数值按比例分配。权重不必总和为 100。

优先级权重 <= count:N

今日 => きょう <= count:100

N 是该规则的优先级权重，默认 1。
同一个 pattern 在多个文件里出现时，N 更大的胜出，直接无视文件名字母序。规则一旦生效会替换全文所有匹配。

💡 典型用法：词典里给条目设高 count 数值（如 <= count:100），保证永远压过其他词典里的同词规则。EPUB 提取工具导出时，出现次数 > 1 的词条会自动追加 <= count:N。

正则替换

(\d+)年 => \1ねん

⚠️ 重要概念：显性 Ruby 与 隐性 Ruby
很多日文 EPUB 或青空文库文本在排版时，会省略注音标记的起始点，这两者的处理逻辑和兼容性有很大区别：
  • 显性 Ruby：例如 ｜東京大学《とうきょうだいがく》。以竖线 ｜ 作为明确的起始点，解析器能就此 100% 准确切分。
  • 隐性 Ruby：例如 「東京大学《とうきょうだいがく》」。没有竖线起点，完全依赖前方的标点符号或汉字边界进行自动识别。
🚨 兼容性警告（古早 TTS 引擎的坑）：
如果你使用其他旧版 TTS 引擎或阅读器，它们可能无法正确识别隐性 Ruby。在解析时，它们极大概率会将原文的汉字和注音框里的汉字同时读出来，导致出现类似 東京東京大学 这样的重复朗读错乱。
💡 解决建议：在导出或提供给其他引擎使用时，建议将隐性 Ruby 全部替换为显性 Ruby（在汉字前手动加上 ｜），以保证最大的兼容性。

  • 无视空格：原文是 終　章（中间有全角空格），写 終章 => しゅうしょう 也能命中。
  • 拦截错注音：如果 EPUB 排版或 OCR 识别时标了完全错误的读音，比如把 協力 错标为 |協力《くきようりよく》（显然是把促音和拗音全拆错了），但只要你的词典里写有 協力 => きょうりょく，系统就会直接废弃 EPUB 自带的错标，强制使用词典里的正确读音。
  • 相邻 ruby 合并：｜一《いつ》｜瞬《しゆん》 → 若词典命中 一瞬 => いっしゅん，则丢弃原注音，交给替换规则。
  • 原文 = 读音：直接返回原词（如 アスナ《アスナ》 → アスナ）。
  • 丢弃重复注音：｜ＮＰＣ《ＮＰＣ》 这种无效标签会自动去重，防止 TTS 读两遍。
  • 数字保护：模式 C 下，对于「数字 + 汉字/量词」的词条，系统不会将注音框错误地套在纯数字上。它经过内部算法处理后，会自动剥离数字并转换，例如：

output: にじゅう｜4本《よんほん》

input: 128人
output: ひゃくにじゅう｜8匹《はっぴき》
    这样既保证了数字部分能被正确朗读，也避免了后续的 本 => ほん 等替换规则产生冲突或重复识别。

  • 点第三下，恢复原样（显示为 组词 ）：不再按组词筛选。

不同分组的文字会稍有不同，但逻辑完全一致：
  • 编辑状态：点第一下是“已勾选/收录/编辑”，点第二下是“未勾选/收录/编辑”。
  • Ruby 小字：点第一下是“含常见/特殊小字”，点第二下是“常见/特殊小字已小字化”（帮你挑出已经纠正过小字状态的词条）。
  • 标记：同理，帮你单独筛出标了名词或存疑的词条。
如果点乱了，直接点击右侧的清空筛选按钮，所有条件就会一键复原。

工具栏支持搜索、排序（五十音 / 正文顺序 / 出现次数）、升降序、全选 / 取消全选当前筛选词条。

⚠️ 疑似小字检测：读音中包含本应写成小字的大字字符时会被标记。
为了方便分类处理，系统将其分为了两类（可通过筛选栏的循环按钮进行过滤）：
🔸 常见小字
检测平假名 やゆよつ，片假名 ヤユヨツ。
如：きよう → 应为 きょう
がつこう → 应为 がっこう
🔹 特殊小字
检测片假名 ケカ 以及 アイウエオ。
如：一ケ月 → 应为 一ヶ月
フアイ → 应为 ファイ

建议：在导出文件后，将这类词条单独复制出来，交给免费的 AI（如 ChatGPT、Kimi、通义千问等）进行批量分析和修正，效率最高。

步骤 4：导出

  • 下载勾选词条：文件名 user_dict_书名.txt，直接放进 📂X:\TTS\replace_rules\ 即可生效，无需重启 tts.py。
  • 下载合并版：把新增词条追加到步骤 2 的参考词典文本后，一起下载。
  • 复制到剪贴板：粘贴到任意编辑器。
  • 🧹 去重：按「汉字 + 读音分布」合并重复条目（单值与多值分开去重），已收录（★）词条只做标签高亮，不会被自动剔除或取消勾选。
  • ❌ 清空当前工作区：彻底清空当前的提取结果、勾选和编辑状态。

导出顺序：

  • 名词 → 疑似小字 → 原文仅西文 → 原文仅片假名 → 组词 → 单字 → 存疑；
  • 组内按出现次数倒序；出现次数 > 1 追加 <= count:N；存疑词条会带上 [?] 标记。
💡 进阶：自动合并与去重机制
当多个不同的汉字组合指向同一注音（如 汉字1 => 注音 和 汉字2 => 注音）时，导出会自动将它们合并为等价规则：汉字1|汉字2 => 注音，并将 count 数值相加。
⚠️ 注意：如果右侧包含多读音概率语法（如 A => B(1)|C(3)），则不参与此合并，原样保留。
💡 为什么需要 AI 辅助？关于自动提取的痛点：
自动提取 EPUB 中的 ruby 后，最多也最繁杂的人工校验工作莫过于：
1. 人名及特定术语：常常出现“写作 A 读作 B”的情况，或者包含特殊的西文/片假名注音。
2. 读音涉及小字：亦即拗音（如 きゃ）或促音（如 っ）在注音时被错误地标成了大字。

然而，人工一行行校验是非常不健康的！为此，本工具在导出文件时专门设计了输出顺序（存疑搁置的条目会被统一放在最末尾，方便最后统一处理）： 
# ===== 名词（n 条） =====
# ===== 疑似小字（n 条） =====
# ===== 原文仅西文（n 条） =====
# ===== 原文仅片假名（n 条） =====
# ===== 组词（n 条） =====
# ===== 单字（n 条） =====
# ===== 存疑（n 条） =====
这前几类容易被机器误判的“重灾区”词条，会被单独列出并放在导出文件的最顶部。你只需要把这几大块直接复制发给免费的 AI（如 ChatGPT、Kimi、通义千问等），让 AI 帮你批量分析和修正，效率瞬间提升百倍。最后再去处理最末尾带有 [?] 标记的存疑项即可。

?? 常见问题Q&A

Q: 黑窗口汉字乱码怎么办？

A: run tts.bat 被保存成了 UTF-8 编码。用记事本打开它 → 另存为 → 编码选择 ANSI（中文 Windows 下即 GBK），覆盖保存即可。

Q: 按 Ctrl + R / F5 没反应？

A: 快捷键只对当前有焦点的黑窗口生效。请先用鼠标点一下黑窗口确保有焦点；并且确认黑窗口里已经打印了「服务已就绪」。

Q: 监控台提示「VOICEVOX 引擎未就绪」？

A: VOICEVOX 没启动，或者端口不是 50021。请先启动 VOICEVOX 引擎，然后按 Ctrl + R 重启一下服务重连。

Q: CeVIO COM 报错「无法连接 CeVIO AI」？

A: 请先启动 CeVIO AI 程序，并确保你的电脑已安装 CeVIO.Talk.RemoteService2 COM 组件（随 CeVIO AI 安装）。

Q: CeVIO 报错「外部接口被占用」？

A: 后台有旧的 Python 进程或 CeVIO 进程没关干净，导致端口/接口死锁。最简单粗暴且最稳的方法是：重启电脑。

Q: 监控台报错 Failed to fetch？

A: 多半是 tts.py 的黑窗口闪退了。重新双击 run tts.bat 启动它即可。

Q: <= count:N 是限制替换次数吗？

A: 不是。它是优先级权重。N 越大优先级越高，直接无视文件名字母序。一旦规则生效，依然会替换全文所有匹配的词语。

Q: [suffix] 规则写了不生效？

A: 必须满足三个条件：
  1. 只能在 person_dict.txt 中写，其他文件无效；
  2. 后缀必须紧跟在已登记的人名之后；
  3. 如果暂时没有人名，写一条 (ダミー) => (ダミー) 占位。

Q: A => B 规则改了为什么不生效？

A: 请依次确认：

  1. 文件在 replace_rules/ 下；
  2. 在监控台里已勾选启用；
  3. 按 Ctrl + R 强制重载。

如果都不行，检查字典里是不是有同词但优先级权重 <= count:N 更高的规则把它覆盖了。

Q: auto_dict.txt 为什么不参与替换？

A: 设计如此。
当原文（如 EPUB）里出现了一个词库里没有的特殊注音时，系统会当场认可并使用这个注音进行朗读，同时把它提取出来登记到 auto_dict.txt 中。
但是，机器（OCR 或 EPUB 制作工具）给出的注音不一定是对的。万一是错标的注音（比如把汉字标成了完全无关的假名），如果直接让它变成了全局替换规则，就会导致以后整本书里所有的这个词都跟着读错，严重污染词库。
因此，auto_dict.txt 必须是“仅登记，不参与后续全局替换”的状态。你需要在监控台打开它，人工确认这些注音没问题后，手动复制到 user_dict.txt 等正式规则文件里，它才会真正变成全局生效的替换规则。

Q: 启动后前端页面没有自动弹出？

A: tts.py 启动后延迟 1.5 秒，如果 1.5 秒内没有任何前端请求才会弹出。手动双击 all in one toolbox.html 也可以，只要保证它和 tts.py 在同一个目录即可。

Q: 能不能在 Linux / macOS 上跑？

A: 不能。 SAPI 语音接口、CeVIO COM 组件、以及 msvcrt 快捷键监听均深度依赖 Windows，且开发者已明确不再做其他系统的移植。

Q: epub以外的格式能不能读？

A: 原则上，只要是能被读取到纯文本的格式都可以。

Q: 我用的某某某阅读器能不能读？

A: 这需要同时满足两个条件：
1. 阅读器本身必须自带 TTS（文本转语音）朗读功能；
2. 它的朗读设置中必须支持接入 OpenAI 接口（或者允许自定义 TTS 引擎的 API 地址）。
只有同时满足这两点，才能成功接入本服务并正常朗读。

Q: 我可以去哪里获得 epub 电子书？

A: 首先，最正当的途径当然是去各大正版电子书平台购买并下载，支持正版永远是第一位的。
根据你需要阅读的语种和类型，可以选择以下正版渠道：

v1.0.13
  • 修复了 <ruby> 逐字注音结构（一个 <ruby> 内含多个 <rt>）无法被解析的 BUG。
  • 根因：tts.py 的 RUBY_PATTERNS 第一条正则只支持「1 个 base + 1 个 rt」的标准结构，遇到 EPUB 里常见的 <ruby>矯<rt>きよう</rt>正<rt>せい</rt></ruby> 这种逐字注音时，正则匹配失败，导致整条 <ruby> 标签被原样保留，最终送进 TTS 引擎的文本里混杂着大量 HTML 标签，被朗读成「ruby 矯 rt きよう …」之类的乱码。
  • 修复：新增 _extract_html_ruby() 专用解析函数，改用 re.split 按 <rt> 边界切片，把多段 base 与多段 ruby 分别拼接合并。矯<rt>きよう</rt>正<rt>せい</rt> 会被正确还原为 ｜矯正《きようせい》，強<rt>きよう</rt>靱<rt>じん</rt> 会被正确还原为 ｜強靱《きようにん》。
  • 同步增强了 <rp> 标签的剥离能力，并支持 <rb>、<span> 等嵌套标签混入的情况。
  • 💡 温馨提示：本次修复只解决「标签解析」，但原文标注的读音是否正确，仍需你自己把关。
    比如 EPUB 常见的错标：矯正 标成 きようせい（よ 应为小字 ょ）、強靱 标成 きようにん（应为 きょうじん）——解析器只能忠实还原原文给的读音，无法自动纠错。
    建议在 user_dict.txt 里加上 矯正 => きょうせい、強靱 => きょうじん 等强制覆盖规则，让词典优先级压过原文 ruby。
v1.0.12
  • 修复了「大小写兼容」算法范围过度扩大化，导致 Windows 讲述人与 Edge TTS 模型调用失败的 BUG。
  • 根因：后端 _do_synthesize() 对整个 model 字符串无差别 .lower()，误伤了 Edge TTS 与 Windows SAPI 这两个大小写敏感的标识符体系。
  • 修复：拆分 model_raw（保原貌）与 model_lower（仅分支判断），edge: / windows: 前缀的语音名一律从 model_raw 提取。
  • 前端新增 normalizeBySelect() 兜底，自动把历史脏数据与手填小写纠正为下拉框里的正确大小写。
  • ⚠️ 特别强调：Windows 讲述人 与 Edge TTS 不支持 C 模式（Ruby 输出），请使用 A（纯汉字） 或 B（纯注音） 模式。
